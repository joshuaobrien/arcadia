# Real playback output verification

`JellyfinPlaybackTests` drives the public macOS UI against the disposable Jellyfin fixture. A separate guest helper captures the actual Arcadia process's outgoing PCM; it contains no player. `verify-audio.py` independently checks rendered play, pause, resume, seeking and natural advancement. Player clocks and successful HTTP requests are insufficient evidence.

Run everything in a disposable, logged-in macOS task VM, with Tart `--no-graphics --no-audio --no-clipboard`. The guest's Apple Virtual Sound Device still supplies the Core Audio clock. Never activate a host viewer or change host capture permissions. Use the existing native-loop source/driver archives, warm DerivedData and private lint cache.

1. Provision the task's disposable Jellyfin fixture using `jellyfin.py`. Its first song, First Contact, is 30 seconds: 520 Hz for the first 15 seconds and 680 Hz for the final 15 seconds. The public restored-session seek of 0.6 lands near 18 seconds and must render 680 Hz. The next song, Persistent State, is 12 seconds at 600 Hz; the separate sustained fixture remains 600 Hz for its requested duration. Copy its private configuration into guest `/tmp/arcadia-jellyfin-fixture.json` with mode0600 and the guest relay URL. Keep credentials outside source and exported evidence.
2. Build a guest-only helper app with `audio-capture.swift` as its executable and `audio-capture.plist` as `Contents/Info.plist`, using the guest SDK and ad-hoc signing. The plist declares the system-audio capture purpose. Compile with the selected Xcode's `swiftc -sdk "$(xcrun --show-sdk-path)"`. Grant system-audio capture only within this disposable guest when requested. Under Tart exec the responsible process can be `tart-guest-agent`; record the observed attribution. Do not edit TCC databases or reusable templates.
3. Create the UI runner's container directory: `/Users/admin/Library/Containers/tokyo.drift.Arcadia.Development.xctrunner/Data/tmp/arcadia-audio-capture-52`. Launch the helper with that directory as its sole argument. It writes `armed`, waits for the UI test's actual app PID, creates a private process tap and aggregate clocked by the default guest output, then writes `capture-ready`. A tap-only aggregate can start without emitting callbacks; missing samples must fail verification.
4. Run the existing guest driver with `only-testing ArcadiaUITests/JellyfinPlaybackTests/testRealAudioTransportSeekAndNaturalAdvancement`. The test starts real playback before publishing the PID, records the phases, seeks to the680Hz segment, observes natural advancement and writes `done`. It uses the runner's own container because sandboxed test code cannot write arbitrary global `/tmp` directories. An unarmed run skips explicitly and does not count as real-audio acceptance.
5. Export the capture directory and the test result before deleting the VM. Run `python3 test-environment/native/verify-audio.py CAPTURE_DIRECTORY`. Require its positive result in addition to the public UI test. Preserve raw PCM, timestamped chunks, phases, target PID, summary, logs and app-window screenshot. Remove the `armed` marker when the helper is no longer running, so later ordinary suites cannot accidentally reuse stale evidence.

The helper validates48kHz stereo Float32 interleaved format. Assertions select settled windows and require meaningful sample counts, nonzero output with the expected independently known tone, and silence while paused. This proves the application's output pipeline in the guest; it does not certify physical speaker acoustics, iOS hardware background audio or CarPlay. Simulator process attribution needs separate verification.

Ticket52 used an approved local Xcode27.1RC template after the standard pinnedOCI image required a cold68GB download. Its manual provenance and evidence are recorded separately; noOCI digest was invented. That local template lacked Mint, so the already cached SwiftLint0.65.1 executable ran directly. Xcode27.1's formatter required a guest-only copy of `.swift-format` adding `orderedImports.shouldGroupImports=false`; repository config and CI were preserved.

### Guest simulator permission preflight

Before an iPhone capture journey, verify that the task's simulator UUID is the only booted device and that Device Hub shows that exact selected device. Keep Device Hub inside the background guest; a host viewer is unnecessary. Refuse existing result bundles, logs and capture/IPC directories before starting children.

Inspect the guest's native UserNotificationCenter as well as the iOS screen. A macOS permission sheet can block the simulator's media broker while the app continues to show Loading; an iOS screenshot cannot reveal that sheet. Record only the prompt's static text, button labels, owned process and decision. Never edit a TCC database or resolve a different application's prompt.

For output-only tests, the exact `SimulatorTrampoline.xpc` microphone prompt concerns unused input: choose **Don’t Allow**. The exact task-agent system-audio recording prompt may be allowed only while the owned output-capture helper is being started. These are separate decisions, not a blanket Allow policy. Check for newly appearing native prompts while the first public playback request is pending.

Run a bounded two-second permission pilot with the accepted tap-only helper before the full journey. Reap its owned child and verify the native modal is gone. A zero-clock pilot proves capture permission, format and live callbacks; it does not prove application audio. Require independent known-tone PCM in the subsequent public UI journey.

## Reproduce the fixture tone contract

On the Docker backend host, run `python3 test-environment/native/verify-fixture-tones.py --output FRESH_OWNED_DIRECTORY`. This uses only the already-pinned image in an ephemeral network-disabled, one-CPU container; it starts no Jellyfin server or app and does not reseed an existing fixture. The generator's actual audio input is encoded to MP3, independently decoded at 2s/18s (expected 520/680 Hz), and checked for meaningful RMS/sample counts and a 30-second duration. The sustained 300-second 600 Hz mode is also decoded early and near its end. The manifest retains source/probe/image/media hashes and actual sample results. Ownership-checked cleanup removes only this probe's container and anonymous volumes; generated MP3/PCM evidence remains in the selected output directory. This backend contract check complements, and does not replace, actual application-output PCM acceptance.
